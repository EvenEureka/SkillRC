skillrc-gate

A release check for agent changes, computed from episode logs

Docs Code Historical report Inspect report

The question

An agent team adds a distilled memory, edits a prompt, or turns on a harness feature. Before shipping: is the new version better or worse on a fixed task set, by how much, at what cost, and if it is worse, which part of the change is responsible? A single before-and-after number cannot answer that, especially when several changes ship together.

The gate reads the logs of both versions on the same tasks and returns one verdict per declared change: PASS BLOCK INCONCLUSIVE INVALID DESCRIPTIVE. The command's exit code is the verdict, so a CI job can stop a release.

What the gate found

  1. A bundled release hid a regression. On 500 WebShop sessions with Qwen3-8B, shipping a page label and a distilled memory together looked like a gain over the old release (Δ +0.132 [+0.089, +0.174]). Split into declared interventions, the label alone gave +0.251 and the memory, given the label, -0.119 [-0.164, -0.075] while adding +55% prompt tokens per episode. These logs predate the provenance contract, so the gate reports them as DESCRIPTIVE: real statistics, no release decision.
  2. The pre-registered release check. Running now: 13 arm-runs in two execution blocks on two GPUs (published memory vs none on sessions 0–499; repaired memory, the published memory and three matched comparator edits on held-out sessions 520–1019). This section is generated from the gate's result file when the runs finish.
  3. Not enough evidence is also a verdict. Through Inspect AI on 96 AgentDojo tasks (two epochs per arm), a block of six tips in the system prompt scored 0.427 vs 0.401 (Δ +0.026 [-0.047, +0.099]): non-inferior within the margin, but its token cost (+21%, interval up to +59%) could neither be shown under the +30% tolerance nor shown to exceed it. The gate returns INCONCLUSIVE and says why; at 96 tasks the smallest detectable score change is about 0.11.

How it works

The gate does not run agents; it reads their logs (SkillRC runner, Inspect AI, or a plain JSONL schema). Each stage passes one thing to the next:

stagewhat it doespasses on
ingestparses each arm's logs into episodes and a run manifest; all runs of an arm must share one fingerprintarms (a broken arm fails only its own targets)
fingerprint checkthe two versions may differ only in the declared interventions; model revision, scorer, serving, environment and every other file hash must match; missing provenance means no decisionundeclared differences (any → INVALID)
pairingbuilds the expected task × repetition grid from a frozen task registry, picks each cell's scored attempt, counts missing and failed cellstask-aligned table
statisticstask-clustered, stratified bootstrap; order-statistic intervals that agree exactly with the p-values; Holm across guardrails; missing cells bound the scoreestimates and intervals
verdictBLOCK if the score interval lies below −δ or a cost limit is confirmed broken; PASS if the score clears −δ and every guardrail stays under its limit; else INCONCLUSIVEone verdict per change, with reasons
reportJSON for machines, Markdown for CI, HTML with behaviour shifts and paired replaysfiles and exit code

Engineering

The producer side is built for unattended GPU runs: every attempt is journaled before it starts; a run resumes only under the same fingerprint; interrupted or truncated records are recovered; a run stops itself after repeated infrastructure failures so its servers can be restarted; each job in a chain checks that its predecessors succeeded (hash-verified markers); state files are published atomically. The contract was reviewed in eleven rounds with an independent reviewer before launch (design, pre-registration and review record); 94 tests and a calibration study (calibration.md) back the decision rules.

Limits

WebShop here is the 1,000-product version with generated goals, fashion-heavy test panels and a 15-step budget; readers are open Qwen3 models. Intervals describe task-sampling uncertainty given the observed execution windows, not future windows. The error budget is nominal: in simulation, the chance of a PASS when the true change sits exactly at the margin was 0.018–0.041 against a nominal 0.025. The margin (0.05) and the cost tolerances (+30%) are illustrative policies fixed before the runs, not recommendations. Which rule caused a loss is tested only through declared ablation arms, never inferred automatically.
